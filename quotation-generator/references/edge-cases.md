# 高复杂度异常边界

本文件只记录服务数据、特殊价格和其他长尾情况。换算、查询和旧单异常分别见 [currency-conversion.md](currency-conversion.md)、[fetch-errors.md](fetch-errors.md) 和 [edit-existing-quotation.md](edit-existing-quotation.md)。

## Markdown 章节格式不一致导致提取失败

API 返回的服务内容中，章节标题格式极不统一：`****费用包含：****`、`****费用包含********：****`、`费用包含：`（无星号）、`****费用不包含：****`（非"费用不含"）等。正则提取（如 `r'费用包含[：:]*\s*\n'`）频繁失败。

按「费用包含」「费用不含」「所需资料」等文字标记识别章节，忽略标题周围的星号和中英文冒号；不得因 Markdown 装饰差异遗漏内容。执行报价任务时只整理数据，不临时修改 fetch/build/validate/verify 脚本。

## services[].documents 为空

部分服务“所需资料”下明确写“无”，这种情况可在 `documents` 中写“无”。如果只是没有返回资料内容，应向用户确认，不得自行把缺失数据解释为“无”；`documents` 仍必须是非空列表。

## `notes` 里混进办理时间免责声明

API 每个服务的「备注」段都带一句样板文：「上述办理时间不包括收集材料时间、检查资料时间、客户签字盖章反馈时间、客户修改或补充资料的时间和文件邮寄时间。」汇总基本信息时极易顺手带进 `notes`。

**处理方式就是从 `notes` 删除**：不要改写成别的措辞，也不必另找位置补写一遍。这句话要表达的信息已由文末标准备注第 1 条完整覆盖。留在这里反而指错——`notes` 渲染在「服务内容」表正下方，而该表只有 序号/服务内容/数量/价格/备注 五列，没有办理时间列；办理时间在更靠后的流程表里。

**报错只说明位置不对，不代表这条要求被废弃。** validate 报错拦下、build 兜底剔除并告警、verify 复核成稿，三处共用这一判定。

## 所需资料及信息列的拆行与层级缩进

1. **先拆行**：一个数组元素只放一行。多行塞进一条时，段落内换行会被压成空格，子项会挤在同一行。
2. **缩进只在行首写全角空格（U+3000）才生效**，1 个＝1 级。半角空格 / NBSP / U+3164 / U+2800 / U+200B 都无效——`quotation_schema` 的 `item.strip()` 会把它们剥掉，填充字符不产生位移。

build 会打印「所需资料及信息行缩进：N 行」；没有这行就说明一条都没标层级。

## 数据与成稿长尾情况

### 测试费作为独立行项

用户要求增加测试费时，新增独立服务行，单列金额；人工行 `ai_code` 填 null，`days` 可填 `-`，并填写简短的流程、交付和材料字段。

### 「条」表示百万印尼盾

用户口语中的「1 条」= 1 juta = 1,000,000 IDR。结构化数据只写数值，不保留「条」字；回复用户时可同时展示换算结果。

### 同名服务与顺序

允许同名服务，每行用唯一 `line_id` 区分。调整顺序时直接重排完整的 `services[]` 对象，不需要同步其他数组。追加时可复用已有 `queried_services.json` 中匹配的 aiCode，避免重复 fetch。

### XML 非法字符或损坏 DOCX

verify 报 `word/document.xml` 非法或 DOCX 不是有效 zip 时，先检查从 Word/PDF 复制的 NUL、ESC、BEL 等控制字符以及未写完文件。正常 build 会通过 `xml_safe_text()` 清理；出现该问题通常说明文件被绕过 build 修改或写入中断。清理数据后重新 build，不要直接编辑成稿 XML。
