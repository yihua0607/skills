# 高复杂度异常边界

以下异常的处理方案从 SKILL.md『修复与异常边界』表拆出，正文表格只保留触发条件 + 一句话要点，完整处理见本文档对应小节。

## 外币 → 外币（API 没有直接汇率）

`rateToCny` / `rateToUsd` 的定义是「外币 ↔ 人民币 / 美元」，所以**两侧都不是人民币/美元时（如 THB→VND、MYR→SGD）API 没有汇率数据**：脚本会拒绝并提示索取。必须**向用户索取**（如「1 THB = N VND」），拿到后 `--cross-rate N`（1 `<from>` = N `<to>`）；若用户给的是反向汇率（1 VND = M THB），取 `1/M` 再传。**不得自己估汇率**。

**币种不在 8 个币种内（如 HKD）**：只要显式传汇率脚本就放行（`--rateToCny` / `--rateToUsd`）；不传则报 `Unknown ... currency`。

其余四类换算（外币 → 人民币/美元、人民币/美元 → 外币、人民币 ↔ 美元）见 SKILL.md『汇率与换算』的对照表。

## 分享链接而非 aiCode

山海图分享链接（`#/products/productDetailInner?sharingRecordId=xxx`）中的 `sharingRecordId` 不是 aiCode，无法用于 `aiCode/resolve` API（返回"AI Code 无效"）。除 `aiCode/resolve` 外的所有产品接口均需登录认证。**不要反复尝试不同 aiCode 组合**——直接告知用户分享链接不可用，要求提供完整的 `服务名-19位数字编码` 格式 aiCode。若是规格化产品（如 ODI 按投资额/股东数定价），同时向用户确认所选规格和价格。

## rateToCny 异常低（服务编码非 ID 前缀）

`rateToCny` 与 IDR 严重不匹配（如 0.6、4.0 而非 ~2250），且服务编码以 MY/VN/SG/TH/EG 等国家前缀开头 → API 币种标记错误，实际为对应国家币种（如 MY=马币、VN=越南盾）。**向用户展示异常**，结合服务编码前缀与同批次服务汇率一致性判断真实币种，确认后按实际币种换算。`_meta` 中注明此异常及判断依据。

## Markdown 格式不一致导致提取失败

API 返回的服务内容中，章节标题格式极不统一：`****费用包含：****`、`****费用包含********：****`、`费用包含：`（无星号）、`****费用不包含：****`（非"费用不含"）等。正则提取（如 `r'费用包含[：:]*\s*\n'`）频繁失败。**方案：使用 `str.find()` 定位关键标记 + 截取文本的方式更可靠**，忽略中间星号。编写 `extract_list(content, start_marker, end_marker)` 函数，基于 `find()` 而非正则。

## services[].documents 为空

部分服务“所需资料”下直接写“无”——API 未返回资料清单。提取结果为 `[]` 会触发 `documents is required and must be a non-empty list`。**必须补兜底**：`documents = extract_list(...) or ["请咨询山海图获取详细资料清单"]`。

## `notes` 里混进办理时间免责声明

API 每个服务的「备注」段都带一句样板文：「上述办理时间不包括收集材料时间、检查资料时间、客户签字盖章反馈时间、客户修改或补充资料的时间和文件邮寄时间。」汇总基本信息时极易顺手带进 `notes`，`validate_data.py` 会直接报错拦下；build 也会兜底剔除并告警。

**处理方式就是从 `notes` 删除**：不要改写成别的措辞，也不必另找位置补写一遍。

原因是 `notes` 渲染在「服务内容」表正下方，而该表只有 序号/服务内容/数量/价格/备注 五列，没有办理时间列——「上述办理时间」在这里指不到任何上文（办理时间在更靠后的流程表里）。

**报错只说明位置不对，不代表这条要求被废弃**：这句话要表达的信息已由文末标准备注第 1 条完整覆盖——「以上办理时间为收集齐所需资料及信息开始的官方办理时间，法定节假日及办证政府机构休息日不算入办理时间」；客户准备材料、签字盖章反馈、文件邮寄都发生在「收集齐资料」之前，本就不计入办理时间。

## `convert_currency.py` 报 `Cannot read query result file`

按顺序排查 `queried_services.json`：

1. **首行不是 `{`** —— fetch 时把 stderr 并进了文件（例如 `... > x.json 2>&1`）。按『查询服务信息』章节重新 fetch，并按内容过滤 `⚠️` 开头的行。**不要用 `tail -n +2` 盲删首行**：正常 JSON 的第一行就是 `{`，删掉它反而会把好文件弄坏，症状正好就是这条报错。
2. **首行正常** —— 文件没写成，或 fetch 本身失败。重新 fetch。

## 换算后价格与官网差 1 元

`convert_currency.py` 取整为 **ROUND_HALF_UP（四舍五入）**，不是截断：18,400,000 ÷ 2,250 = **8,178**。

1.16.2 之前的文档误写成「截断得 8,177」，已导致 5 张历史单各少算 1 元（如 VND 80,000,000 ÷ 3,893.98 成稿写成 20,544、应为 20,545）。

**遇到差异先与用户确认采用哪个口径，不要自行改写已交付价格。**

## 所需资料及信息列的拆行与层级缩进

1. **先拆行**：一个数组元素只放一行。多行塞进一条时，段落内换行会被压成空格，子项会挤在同一行。
2. **缩进只在行首写全角空格（U+3000）才生效**，1 个＝1 级。半角空格 / NBSP / U+3164 / U+2800 / U+200B 都无效——`quotation_schema` 的 `item.strip()` 会把它们剥掉，填充字符不产生位移。

build 会打印「所需资料及信息行缩进：N 行」；没有这行就说明一条都没标层级。
