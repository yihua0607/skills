# 报价单生成器 (Quotation Generator)

基于山海图内置模板，为客户生成标准格式的 .docx 报价单。

> **核心要求：必须仔细核对签约主体、服务价格、小计、增值税率、增值税、含税总计。确认格式整齐、无乱码无错位。**

## 模板概览

三个模板已内置在 `assets/` 中：

| 模板 | 文件 | 适用签约主体 | 币种 | 增值税 |
|------|------|-------------|------|--------|
| 西安 | `报价单模板-西安公司.docx` | 北京/西安/上海/上海新企业 | ¥ 人民币 | 6% 或 1% |
| 深圳 | `报价单模板-深圳公司.docx` | 深圳 | ¥ 人民币 | 6% |
| 雅加达 | `报价单模板-雅加达公司.docx` | 雅加达 | Rp 印尼盾 | 11% |

### 模板共同结构（8 大模块）

1. **头部信息**：公司名称、联系人、联系方式、报价日期、订单号、服务方案标题
2. **服务内容表**：序号、服务内容、时间（工作日）、价格（总价）、备注
3. **费用汇总**：小计 → 优惠金额 → 增值税 → 含税总计
4. **备注说明**：费用包含/不含、注意事项
5. **付款条件**
6. **服务流程及交付材料清单**（表格；每项独立段落）
7. **所需材料清单**（表格；每项独立段落）
8. **尾部**：银行账户信息、保密条款、报价有效期 30 天、双方签字栏

## 工作流程

### 第一步：确定签约主体

用户未指定时，主动列出选项让其选择：

| # | 签约主体 | 公司全称 | `--template` | `--entity` | 增值税 |
|---|----------|----------|-------------|-----------|:---:|
| 1 | 雅加达 | PT. SHAN HAI MAP | `jakarta` | — | 11% |
| 2 | 北京 | 北京山海图科技有限公司 | `xian` | `beijing` | 6% |
| 3 | 西安 | 北京山海图科技有限公司西安分公司 | `xian` | `xian` | 6% |
| 4 | 深圳 | 北京山海图科技有限公司深圳分公司 | `shenzhen` | — | 6% |
| 5 | 上海 | 北京山海图科技有限公司上海分公司 | `xian` | `shanghai` | 1% |
| 6 | 上海新企业 | 上海山海图新企业咨询有限公司 | `xian` | `shanghai_new` | 1% |

签约主体决定模板、币种、税率和银行账户。生成时按上表传 `--template` 和 `--entity`（如有）参数。银行信息见文末速查表。

### 第二步：收集服务信息

每个服务的**名称、数量、总价、办理时间（工作日）、基本信息**。
仅接受总价。如果用户给了单价，要求其提供总价。
基本信息从用户提供的 .docx/.pdf 文档中提取，或从用户在输入框中直接发送的服务信息中获取。

**币种转换：** 如果用户提供的价格是印尼盾但需要人民币报价（或反之），询问汇率。建议使用 `CNY:IDR = 1:2250` 进行转换。转换后：服务价格四舍五入取整数，增值税和含税总计保留 2 位小数。印尼盾全部取整数，不允许小数。

> 以下无需询问用户：
> - 报价日期 → 默认当天
> - 客户公司名称、联系人、联系方式、订单号 → 可留空
> - 优惠金额 → 无则填 0

> ⚠️ **优惠/打折商业规则**：优惠金额只在**税前小计**上扣减，即先用小计减去优惠，再计算增值税；不支持在税后金额/含税总价上优惠。

> 以下信息忽略，不写入报价单：退款/售后政策、发票相关、付款方式。

### 第三步：计算费用

1. 小计 = 各服务总价之和（整数）
2. 优惠后价格 = 小计 − 优惠金额
3. 增值税 = 优惠后价格 × 税率
4. 含税总计 = 优惠后价格 + 增值税
5. 费用汇总行显示"优惠金额"（即减少的金额），而非优惠后价格

> **固定规则：优惠金额只作用于税前小计。** 不支持税后金额/含税总价优惠；即使用户提到含税总价优惠，也必须按税前小计优惠口径重新确认。

**人民币示例（北京/西安/深圳，6%，税前优惠）：**
```
小计:        ¥255,556
优惠金额:     ¥5,000
增值税 6%:   ¥15,033.36    ← (255,556 − 5,000) × 6%
含税总计:    ¥265,589.36
```

**印尼盾示例（雅加达，11%）：**
```
小计:        Rp 380,000,000
增值税 11%:  Rp  41,800,000
含税总计:    Rp 421,800,000
（无优惠，不显示优惠金额行）
```

> ⚠️ "优惠金额"行显示**减少的金额**；无优惠时不显示该行。

### 第四步：编写备注

从"基本信息"总结 **100–200 字**。不足 100 字则完整呈现。

### 第五步：填写数量与价格列

- 价格列只填**总金额**（整数），不填单价
- 数量 = 1 → 服务内容列只显示名称
- 数量 > 1 → 只在服务内容表显示 `服务名称×N`
- 后面的备注说明、服务流程及交付材料清单、所需材料清单中的服务名不显示数量
- 价格列数字 **10pt**，必须完整显示在一行内，不能换行

### 第六步：准备数据文件并生成

复制 `examples/sample_quotation.json` 为本次报价的数据文件，按本次服务内容编辑 JSON，再运行脚本。不要修改 `scripts/build_quotation.py` 里的生成逻辑。

```bash
# 深圳/北京/西安（增值税 6%，默认）：
python3 scripts/build_quotation.py --template shenzhen --data quotation.json --output 报价单.docx
# 西安模板 + 指定签约主体：
python3 scripts/build_quotation.py --template xian --entity xian --data quotation.json --output 报价单.docx
# 上海/上海新企业（增值税 1%，通过 --entity 自动识别）：
python3 scripts/build_quotation.py --template xian --entity shanghai --data quotation.json --output 报价单.docx
# 雅加达（增值税 11%，默认）：
python3 scripts/build_quotation.py --template jakarta --data quotation.json --output 报价单.docx
# 自定义标题：
python3 scripts/build_quotation.py --template shenzhen --data quotation.json --title-line1 "印尼投资" --title-line2 "公司注册服务方案" --output 报价单.docx
```

| 参数 | 说明 |
|------|------|
| `--template` | `xian` / `shenzhen` / `jakarta` |
| `--entity` | `xian`(默认) / `beijing` / `shanghai` / `shanghai_new`。西安模板必传，决定银行信息、签名公司、增值税率 |
| `--vat-rate` | 手动覆盖增值税率（如 `0.06`）。上海实体通过 `--entity shanghai` 自动设为 1%，无需手动传 |
| `--title-line1` | 标题第一行（默认 `印尼投资`） |
| `--title-line2` | 标题第二行（默认 `综合服务方案`） |
| `--data` | 本次报价数据文件，支持 `.json`；`.yaml/.yml` 需当前环境安装 PyYAML |
| `--output` | 输出路径 |

### 数据文件清单

本次报价数据必须放在外部 JSON/YAML 文件中，推荐从 `examples/sample_quotation.json` 复制后编辑。脚本会在生成前自动校验；校验失败时会停止，不生成报价单。

| 字段 | 对应模板模块 | 是否必填 | 格式说明 |
|------|-------------|:---:|------|
| `services` | 2.服务内容表 | ✅ | 分组列表；每个服务含 `id`、`name`、`quantity`、`days`、`price`、`note`；`name` 写基础服务名，不加 `×N` |
| `discount_amount` | 费用汇总 | 视情况 | 优惠金额整数；无优惠填 `0` 或省略；不能大于小计 |
| `notes` | 4.备注说明（通用备注） | 视情况 | `{"text": "...", "indent": 360}` 列表 |
| `fee_details` | 4.备注说明（费用包含/不含） | ✅ | 每项含 `name`、`include`、`exclude`、`note` |
| `process_data` | 6.服务流程及交付材料清单 | ✅ | 每项含 `name`、`process`、`deliverables` |
| `doc_data` | 7.所需材料清单 | ✅ | 每项含 `name`、`docs` |
| `doc_notes_text` | 材料清单下方备注文本 | 视情况 | 字符串列表，每段独立成段 |

> ⚠️ **关键约束：** `services` 中的 `name` 必须写基础服务名，数量写在 `quantity`。脚本只在服务内容表自动显示 `×N`；`fee_details` / `process_data` / `doc_data` 中的 `name` 必须与基础服务名完全一致，不要加数量标记。

自动校验包括：必填字段、数量为大于等于 1 的整数、服务名不含 `×N/xN` 数量后缀、价格/优惠为整数、优惠金额不能大于小计、基础服务名称唯一、费用说明/流程/材料覆盖所有服务、多行字段为非空列表。脚本自动完成：读取数据 → 校验 → 解包模板 → 替换 body → 保留 sectPr（A4）→ 打包 → 清理临时文件。

### 第七步：交付前校对

报价单涉及金额和签约信息，一处错误就影响客户信任。生成后逐项核对，确认无误后再交付。

**格式检查：**
- [ ] 节标题（1.服务内容、2.付款条件、3.服务流程及交付材料清单、4.所需材料清单）样式一致
- [ ] 字体：全文仿宋（FangSong），无混入
- [ ] 标题：蓝色 #4472C4，居中，底部蓝色边框线
- [ ] 表头：浅蓝底色 #BDD6EE，粗体居中
- [ ] 表格：边框完整，列宽合理，无错位
- [ ] 多行内容：流程/交付文件/材料清单每项独立成行
- [ ] 页面：A4（210mm×297mm）
- [ ] 字符：无乱码、方块、问号

**金额验算（用计算器逐项复核）：**
- [ ] 各服务总价正确、币种正确
- [ ] 小计 = 各服务总价之和
- [ ] 优惠金额 = 减少的金额（非优惠后价格）；无优惠则不存在该行
- [ ] 增值税 = (小计 − 优惠金额) × 税率
- [ ] 含税总计 = (小计 − 优惠金额) + 增值税
- [ ] 人民币：增值税和含税总计 2 位小数；其余整数
- [ ] 印尼盾：全部整数，无小数点
- [ ] 所有数字千分位正确，无多打少打

**最终确认：**
- [ ] 报价日期 = 当天
- [ ] 签约主体、银行账户信息正确
- [ ] 已转 PDF 做最终排版确认（推荐）

## 关键格式规则

### 规则 1：多行独立段落
每个步骤/文件/材料必须是独立的 `<w:p>`，不能用 `\n` 拼接。

### 规则 2：不添加冗余分类标题行
仅在一个分类下有多个子服务时使用合并行。

### 规则 3：基于模板 XML 编辑
禁止 docx-js 从零创建。字体 FangSong、标题 #4472C4、表头 #BDD6EE。

### 规则 4：优惠金额
"优惠金额"行显示减少的金额；无优惠不显示。
**固定规则：优惠金额只作用于税前小计**，即 `增值税 = (小计 − 优惠金额) × 税率`，`含税总计 = (小计 − 优惠金额) + 增值税`。不支持税后金额/含税总价优惠。

### 规则 5：A4 纸张
11906 × 16838 DXA，脚本自动保留 sectPr。

### 规则 6：精度

| 行 | ¥ 人民币 | Rp 印尼盾 |
|------|------|------|
| 服务价格/小计/优惠 | 整数 | 整数 |
| 增值税 | **必须 2 位小数** | 整数 |
| 含税总计 | **必须 2 位小数** | 整数 |

### 规则 7：价格不换行
价格列 1800 DXA + 10pt 字体，确保数字完整显示。

## 常见错误

| 错误 | 正确做法 |
|------|----------|
| 用 docx-js 从零创建 | 基于模板 XML 编辑 |
| `\n` 拼接多行内容 | 每行独立 `<w:p>` |
| 人民币增值税少小数位 | 必须 2 位（如 1,800.00） |
| 印尼盾出现小数 | 四舍五入到整数 |
| 优惠理解反了 | 显示减少的金额 |
| 优惠在含税总价/税后金额上操作 | 不支持；优惠金额只能扣减税前小计 |
| 分类标题行冗余 | 仅子服务时使用 |
| sectPr 丢失 | 脚本自动保留，需验证 |
| 价格数字换行 | 10pt + 1800 DXA 列宽 |
| 数量放备注中，或把数量写进后续表格项目名 | 数量写入 `services[].items[].quantity`；只有服务内容列自动显示 `×N` |
